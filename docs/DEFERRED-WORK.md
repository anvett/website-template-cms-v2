# DEFERRED-WORK.md — Registro central de pendientes

**Proyecto:** Template Web CMS v2
**Última actualización:** 2026-09-09 (DW-008 Bloque E6 implementado -- Site + Page + Navigation editables reutilizando el motor genérico existente, sobre el PASO 0 ya auditado; DW-069/DW-070 sin cambios, siguen abiertos)
**Origen:** consolidado desde `AUDITORIA-EXTERNA-TEMPLATE-CMS-V2.md` (`AUD`), `ANALISIS-API-PARA-PANEL-CMS-CLIENTE.md` (`API`), `ANALISIS-EDITOR-CMS-DINAMICO.md` (`DYN`), `DISENO-TECNICO-EDITOR-ANVETCORP.md` (`DES`), `INFORME-PASO-1-METADATA-SECTIONS.md` (`SEC`), `ANALISIS-METADATA-GLOBAL-SITE-NAVIGATION-PAGE.md` (`GLB`), `CMS-UNIFIED-METADATA-CONTRACT.md` (`UMC`, DEC-UMC-01 a 08).

**Qué es este archivo:** el estado operativo de cada pendiente identificado en el proyecto — categoría, prioridad, gate (momento máximo de cierre) y estado actual. El razonamiento detallado de cómo se identificó cada uno sigue viviendo en su documento de origen; este archivo no lo repite.

**Campos de cada entrada:** ID (estable, nunca se reutiliza), Título, Categoría, Origen, Descripción, Impacto/Riesgo, Prioridad, Gate, Estado, Dependencias, Criterio de cierre.

**Prioridad (`Priority`) — importancia relativa:**
- `P0`: bloquea el objetivo actual (completar el Editor Anvetcorp / motor de metadata) o representa un riesgo que obligatoriamente debe resolverse antes de su `Gate`.
- `P1`: importante para completar correctamente el producto, pero no bloquea el paso actual.
- `P2`: mejora, deuda de bajo impacto, o capacidad futura.

**Gate — momento máximo en que debe estar resuelto (independiente de la prioridad):**
- `NOW`: debe resolverse en el ciclo de trabajo actual, con independencia de si bloquea o no otra cosa.
- `BEFORE_CLIENT_EDITOR`: debe resolverse antes de dar acceso al panel a un `client_editor` real (persona no técnica de un cliente).
- `BEFORE_PRODUCTION`: debe resolverse antes de desplegar o vender el producto correspondiente a un cliente real en producción.
- `BEFORE_ECOMMERCE`: debe resolverse antes de vender/lanzar el módulo de ecommerce (`storefront`) a un cliente real.
- `WHEN_REQUIRED`: se resuelve solo cuando surja una necesidad real concreta (un cliente real lo pide) — no tiene fecha límite propia.

**Regla de mantenimiento permanente:** ninguna tarea futura (informe, análisis o implementación) puede cerrar indicando "pendiente", "fuera de alcance", "posterior", "deprecado", "no implementado" o equivalente sin crear o actualizar la entrada correspondiente en este archivo. El documento de origen conserva el razonamiento; este archivo conserva el estado.

**Resumen cuantitativo:** 70 entradas. Categoría: 3 `BUG`, 27 `DEFERRED_FEATURE`, 18 `TECH_DEBT`, 6 `DOC_GAP`, 14 `DECISION_PENDING`, 2 `DEPRECATED`. Prioridad: 11 `P0`, 27 `P1`, 32 `P2`.
